# アプリにする

このテンプレートのコピーを、自分のアプリに変える手順。サンプル（投稿アプリ）のうち、何を残し、何を消し、何を置き換えるかを決める。各手順の中身は、リンク先の資料が持つ。

## 1. コピーして動かす

* テンプレートの履歴を持ち込まないコピーを作る: `git archive HEAD | tar -x -C <新しい場所>`。作ったら、そこで `git init` する。
* Node を合わせる: `nvm use`（`.nvmrc` が 24 を指す）。`node -v` で確かめる。`engines` は宣言だけなので、別の版でも `npm install` は通ってしまう。
* `npm install`、`cp .env.example .env.local` を実行する。
* `npm run lint`・`npm run typecheck`・`npm test`・`npm run e2e` が通ることを確かめてから、変更を始める（[開発環境と設定](./開発環境と設定.md#スクリプト)）。

## 2. 名前を置き換える

* `package.json` の `name`、`app.json` の `name`・`slug`・`scheme` を、アプリの名前に置き換える。
* `ios.bundleIdentifier`・`android.package` を決める（[app.json の既定](./開発環境と設定.md#appjson-の既定)）。

## 3. サンプルを整理する

| 区分                 | 対象                                                                                                                                                                                    | 扱い                                                                                                       |
| -------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| テンプレートの一部   | `src/components/`、`src/theme.ts`・`src/hooks/use-theme.ts`、`src/api/` の `mutator.ts`・`query-client.ts`・`auth-state.ts`・`token-storage*.ts`、`src/constants.ts`、`e2e/mock-api.ts` | 残す。`theme.ts` の色は書き換える                                                                          |
| 認証のサンプル       | `src/features/auth/`、`src/hooks/use-current-user.ts`、`src/features/settings/components/account-section.tsx`                                                                           | 認証の方式が同じなら、残して API の路を合わせる。違うなら[認証](./認証.md)に従って作り直す                 |
| 見本として置いたもの | `src/features/posts/`、`src/app/posts/`、`src/app/(tabs)/index.tsx` の中身、`src/utils/format-full-name.*`、`e2e/posts.spec.ts`                                                         | 自分の feature に置き換える（使うものは残す）                                                              |
| 永続化の見本         | `src/hooks/use-display-name.ts`、設定の「表示名」                                                                                                                                       | 要らなければ消す。消したら、使っていた `@react-native-async-storage/async-storage` を `npm uninstall` する |

* 依存を消すときは `npm uninstall <パッケージ>` を使う。
* 画面名（`_layout.tsx` の `Stack.Screen`、`Tabs.Screen`）、`e2e/auth.spec.ts` の、ログイン後に出る文言は、自分の画面に合わせる。

## 4. API を自分のものにする

* `src/api/openapi.yaml` を、自分の API の契約に置き換える（ログインと、ユーザー情報の取得を含める）。認証もデータも、同じ `openapi.yaml` に書く。
* `npm run generate` で生成し直す。契約から無くなった操作の出力は、`orval.config.ts` の `clean: true` が消す。
* 接続先は `EXPO_PUBLIC_API_BASE_URL`（`.env.example`、`.env.local`、CI の `env`、`playwright.config.ts` の `webServer.env`）。[環境変数](./開発環境と設定.md#環境変数)
* バックエンドが複数あるときは、[接続先が複数あるとき](./選定ライブラリ.md#付録接続先が複数あるとき)。

## 5. CLAUDE.md と README.md

* `CLAUDE.md`: 先頭の説明を、アプリの説明に書き換える。「資料」と「常に守ること」の索引は、そのまま残す。アプリ固有の決め事は、規則の本文を `docs/` の該当する資料に書き、`CLAUDE.md` の索引に足す。
* `README.md`: アプリの説明、実行手順に書き換える。サンプルの説明は消す。
* `docs/`: アプリの規約として、そのまま育てる。アプリに合わせて直してよい。

## 6. 通す

[完了の報告](./AIとの進め方.md#完了の報告)の検査に加えて、`npm run generate`（生成物に差分がない）、`npx expo-doctor`、`npx expo export` が通ることを確かめる。CI と同じ検査は[CI](./開発環境と設定.md#cigithub-actions)。
