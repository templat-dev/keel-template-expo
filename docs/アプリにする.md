# アプリにする

このテンプレートのコピーを、自分のアプリに変える手順。サンプル（投稿アプリ）のうち、何を残し、何を消し、何を置き換えるかを決める。各手順の中身は、リンク先の資料が持つ。

## 1. コピーして動かす

* テンプレートの履歴を持ち込まないコピーを作る: `git archive HEAD | tar -x -C <新しい場所>`。作ったら、そこで `git init` し、**最初のコミットを作る**（テンプレートの状態を基準にして、以降の変更を差分で確かめる）。
* Node を合わせる: `nvm use`（`.nvmrc` が 24 を指す）。`node -v` で確かめる。AI がコマンドを実行する環境では、コマンドごとに `nvm use` を前置する（[依存パッケージ](./開発環境と設定.md#依存パッケージ)）。
* `npm install`、`cp .env.example .env.local` を実行する。
* 初回だけ、`npx playwright install chromium` でブラウザを入れる（[初回の準備](./テスト.md#初回の準備)）。
* `npm run lint`・`npm run typecheck`・`npm test`・`npm run e2e` が通ることを確かめてから、変更を始める（[開発環境と設定](./開発環境と設定.md#スクリプト)）。

## 2. 名前を置き換える

* `package.json` の `name`、`app.json` の `name`（ホーム画面に出る表示名。日本語でもよい）・`slug`・`scheme`（小文字の識別子。URL に使う）を、アプリの名前に置き換える。`package.json` を変えたら、`npm install` を実行する（`package-lock.json` の名前も追従する）。
* `ios.bundleIdentifier`・`android.package` を決める。逆ドメイン形式で、組織が決まっていなければ、`com.example.<名前>` を仮に置いてよい。最初の EAS ビルドの前に決める（[app.json の既定](./開発環境と設定.md#appjson-の既定)）。

## 3. サンプルを整理する

| 区分 | 対象 | 扱い |
| --- | --- | --- |
| テンプレートの一部 | `src/components/`、`src/colors.json`・`src/theme.ts`・`src/hooks/use-theme.ts`、`src/api/` の `mutator.ts`・`query-client.ts`・`auth-state.ts`・`token-storage*.ts`、`src/constants.ts` | 残す。`colors.json` の色は書き換える |
| E2E の API の差し替え | `e2e/mock-api.ts` | 残すが、**中身は書き換える。** データ、API のパスの判定（`isApi`）、画像の判定を、自分の API に合わせる。直さないと、新しい API への通信が差し替えられず、実在しないホストに届く |
| 認証のサンプル | `src/features/auth/`、`src/hooks/use-current-user.ts`、`src/features/settings/components/account-section.tsx` | 認証の方式が同じなら、残して API の路を合わせる。違うなら[認証](./認証.md)に従って作り直す。ログイン画面の「サンプルのユーザー」の表示は、ダミー API 用なので消す |
| 見本として置いたもの | `src/features/posts/`、`src/app/posts/`、`src/app/(tabs)/index.tsx` の中身、`src/utils/format-full-name.*`、`e2e/posts.spec.ts` | 自分の feature に置き換える（使うものは残す） |
| 永続化の見本 | `src/hooks/use-display-name.ts`、設定の「表示名」 | 要らなければ消す。消したら、使っていた `@react-native-async-storage/async-storage` を `npm uninstall` する（お気に入りの保存など、自分のアプリで使うなら残す） |

* 消す前に、消すものを import しているファイルを探す（`grep -rn <名前> src`）。例: `account-section.tsx` は `format-full-name` を import している。
* 置き換えた結果、共通フォルダのものが 1 つの feature でしか使われなくなったときは、[昇格ルール](./フォルダ構成.md#3-昇格ルール共通フォルダへの移動)に従う。
* 色を変えるときは、`src/colors.json` だけを直す（`className` の色も、JS の色も変わる。[色](./選定ライブラリ.md#色デザイントークン)）。
* 画面の構成（タブの数と名前）を決める。`src/app/(tabs)/_layout.tsx` の `Tabs.Screen` と、`src/app/` の route を増減し、`_layout.tsx` の `Stack.Screen` の画面名も合わせる。
* 依存を消すときは `npm uninstall <パッケージ>` を使う。
* `e2e/auth.spec.ts` の、ログイン後に出る文言は、自分の画面に合わせる。

## 4. API を自分のものにする

* `src/api/openapi.yaml` を、自分の API の契約に置き換える（ログインと、ユーザー情報の取得を含める）。認証もデータも、同じ `openapi.yaml` に書く。
* `npm run generate` で生成し直す。契約から無くなった操作の出力は、`orval.config.ts` の `clean: true` が消す。
* 接続先は `EXPO_PUBLIC_API_BASE_URL`（`.env.example`、`.env.local`、CI の `env`、`playwright.config.ts` の `webServer.env`）。接続先が今のままなら、環境変数は変えなくてよい。[環境変数](./開発環境と設定.md#環境変数)
* バックエンドが複数あるときは、[接続先が複数あるとき](./選定ライブラリ.md#付録接続先が複数あるとき)。

## 5. CLAUDE.md、README.md、docs/

* `CLAUDE.md`: 先頭の説明を、アプリの説明に書き換える。「資料」と「常に守ること」の索引は、そのまま残す。
* アプリ固有の決め事は、新しい資料 `docs/<アプリ名>の仕様.md` に、規則の本文を書く。`CLAUDE.md` の「資料」の表に 1 行、「常に守ること」の索引に規則を足す。`docs/` の既存の資料は、テンプレート共通のルールなので、アプリ固有の決め事は書かない。
* `README.md`: アプリの説明、実行手順に書き換える。サンプルの説明は消す。
* `docs/アプリにする.md` と、`CLAUDE.md` の資料の表の「アプリにする」の行は、派生アプリでは使わないので、消してよい。
* `docs/` の既存の資料は、アプリの規約として育てる。サンプルを消すと、資料の例（`PostList`、`posts/new`、`useDisplayName` など）が実物に無くなる。自分のアプリの対応するファイルに書き換えるか、参照を消す。

## 6. 通す

[完了の報告](./AIとの進め方.md#完了の報告)の検査に加えて、`npm run generate`（生成物に差分がない）、`npx expo-doctor`、`npx expo export` が通ることを確かめる。CI と同じ検査は[CI](./開発環境と設定.md#cigithub-actions)。シミュレータでの目視は、開発ビルドで行う（[開発ビルドの作り方](./開発環境と設定.md#開発ビルドの作り方)）。
