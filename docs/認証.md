# 認証

認証を持つ Expo アプリの、トークンの保存と扱いのルール。置き場は[フォルダ構成](./フォルダ構成.md)、使うライブラリは[選定ライブラリ](./選定ライブラリ.md)が持つ。本資料は「トークンをどこに保存し、どう扱うか」を扱う。

サンプルは、ユーザー名とパスワードでログインし、アクセストークンだけを扱う。OAuth などの方式は、アプリごとに決める。リフレッシュトークンによるアクセストークンの更新も、このテンプレートの範囲に入れない。必要なアプリが足す。

## 保存先

| プラットフォーム | 保存先                                              | 理由                                                                                    |
| ---------------- | --------------------------------------------------- | --------------------------------------------------------------------------------------- |
| ネイティブ       | `expo-secure-store`                                 | iOS は Keychain、Android は Keystore で暗号化される。Expo Go でも動く                   |
| Web              | `httpOnly` Cookie（サーバーが `Set-Cookie` で設定） | JavaScript から読めないため、XSS でトークンが盗まれにくい。フロントはトークンを持たない |

* **`localStorage`・`sessionStorage`・`atomWithStorage`（AsyncStorage）には入れない。**
* `expo-secure-store` は Web に対応していない。
* Web の Cookie 認証は、バックエンドが対応している必要がある（`Set-Cookie`、CORS の資格情報、CSRF 対策）。対応していないアプリは、トークンをメモリ上でだけ持つ（リロードでログアウトする）。

### Web の Cookie が送られる条件

ブラウザが Cookie を送るのは、アプリと API が**同じサイト**（例: `app.example.com` と `api.example.com`）にあるとき。

* サンプルの接続先（`dummyjson.com`）は、開発中の `localhost` とは別のサイトで、Cookie に `SameSite` の指定がない（Chrome は `Lax` として扱う）。そのため Cookie が送られず、**実物に繋いだ Web では、ログインできても、リロードすると `/auth/me` が 401 になり、ログイン画面に戻る**（実測）。
* ログイン応答のユーザーをキャッシュに入れてあるので、リロードするまでは画面を使える。
* Web の自動テストは、API を差し替えて「Cookie が届く」状態を作るので、この制約の影響を受けない（[テスト](./テスト.md#api-の差し替え)）。
* ネイティブは `Authorization` ヘッダで送るので、サイトの違いに関係なく動く。

## 通信

mutator（`src/api/mutator.ts`）が、プラットフォームごとに認証を付ける。

* ネイティブ: `Authorization: Bearer` ヘッダを付ける。
* Web: `credentials: "include"` で Cookie を送る。トークンのヘッダは付けない。
* **トークンは、それを発行した接続先にだけ送る。** 接続先が複数あるときは、mutator を接続先ごとに作り、認証を付けるかを接続先ごとに決める（[選定ライブラリ](./選定ライブラリ.md#接続先が複数あるとき)）。認証のない接続先へ送ると、トークンが漏れる。

## 認証状態

認証状態は、メモリ上の Jotai の atom（`src/api/auth-state.ts` の `authAtom`）で持つ。`atomWithStorage` は使わない。

| 状態              | 意味                                                          |
| ----------------- | ------------------------------------------------------------- |
| `loading`         | 起動時の復元が済むまで                                        |
| `unauthenticated` | 未ログイン                                                    |
| `authenticated`   | ログイン済み。`token` はネイティブだけが持つ（Web は `null`） |

* 起動時（`features/auth/hooks/use-restore-auth.ts`）
  * ネイティブ: `expo-secure-store` からトークンを読み、atom に載せる。
  * Web: `GET /auth/me` でログイン済みかを確かめる（トークンはフロントにないため）。
  * 済むまで状態は `loading` で、**ルートの `_layout` は画面を描かない。** 先に描くと、ログイン済みでも、一瞬だけ未ログインの画面が出る。
* 「どの URL に誰が入れるか」は、ルートの `_layout` の `Stack.Protected` で書く。未ログインはログイン画面だけに入れる。ログイン済みでは、ログイン画面に入れない。ログイン・ログアウトで状態が変わると、画面が切り替わる。
* ログイン成功のとき（`features/auth/hooks/use-login-and-sign-in.ts`）: キャッシュを消してから、ログイン応答のユーザーをキャッシュに入れ、トークンを保存し、atom を更新する。キャッシュを消すのは、401 で未ログインに戻されたあと（ログアウトを通っていない）に、別のユーザーでログインしても、前のユーザーのデータが残らないようにするため。
* 401 を受けたとき: mutator が `getDefaultStore()` で認証状態を未ログインに戻し、`expo-secure-store` の値も消す（`resetAuth`）。
* ログアウトのとき（`signOut`）: 次の 3 つをすべて消す。
  * 認証状態の atom
  * `expo-secure-store` の値
  * TanStack Query のキャッシュ（`queryClient.clear()`）。前のユーザーのデータが、次のユーザーに見えないようにする。
* **Web では、ログアウトで Cookie を消せない**（`httpOnly` はフロントから触れない）。Cookie を失効させるログアウトの API をバックエンドに持たせ、ログアウトで呼ぶ。サンプルの DummyJSON にはその API がないので、呼んでいない。

## 置き場

プラットフォーム別コードのルールに従い、ファイルを分ける。mutator が使うので、`src/api/` に置く。

```
src/api/
├── auth-state.ts          # 認証状態の atom、401 での戻し（resetAuth）、ログアウト（signOut）
├── token-storage.ts       # ネイティブ: expo-secure-store に保存・読み出し・削除
└── token-storage.web.ts   # Web: 何もしない（Cookie はサーバーが持つ）
```

2 つの `token-storage` で、関数の形（`get`・`set`・`clear`）を揃える。呼ぶ側は `import * as tokenStorage from './token-storage'` と書く。

ログイン画面・ログイン後の処理・起動時の復元は、`features/auth/` に置く。ログアウトは、設定の画面から `signOut` を呼ぶ（feature 同士は import できないので、`signOut` は `src/api/` にある）。

## 注意点

* `requireAuthentication`（生体認証）は Expo Go で動かないので、既定では使わない。
* 保存・読み出しは `try/catch` で囲む（認証がキャンセルされたり、失敗したりするとエラーになる）。`token-storage.ts` は、失敗を「未保存」として扱う。
* iOS では、アプリを再インストールしても値が残ることがある。保証されないので、前提にしない。
* 古い iOS では、約 2048 バイトを超える値が拒否されたことがある。JWT のように長いトークンを入れるときは注意する。
