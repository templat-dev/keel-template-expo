# テスト

Expo アプリのテスト方針。置き場は[フォルダ構成](./folder-structure.md)、使うライブラリは[選定ライブラリ](./tech-stack.md)が持つ。本資料は「何をどのテストで確かめるか」を扱う。

## 方針

| 層                       | 採用                | 対象                                                             | 置き場                           |
| ------------------------ | ------------------- | ---------------------------------------------------------------- | -------------------------------- |
| 単体テスト               | Vitest（node 環境） | 純粋なロジック（入力と出力だけで完結する関数）                   | 対象の隣に `*.test.ts`           |
| E2E テスト               | Playwright          | Web 版（react-native-web）の画面操作。利用者が達成する一連の流れ | リポジトリ直下の `e2e/*.spec.ts` |
| 画面のレンダリングテスト | **書かない**        |                                                                  |                                  |
| 見た目の確認             | 人間が目視          |                                                                  |                                  |

画面のレンダリングテストを書かない理由は、React Native のレンダリングは環境構築が重く壊れやすいわりに、見た目の妥当性までは判定できないため。

## 単体テスト（Vitest）

* 対象は `src/` 配下の `*.test.ts`。node 環境で動くため、`react-native` を import するファイルは対象にならない。
* **計算・検証などの判断は、副作用のない純粋な関数に寄せて書く**（feature の `utils/` に置く）。画面や hook の中に判断を埋め込むと、テストで確かめられない。
* 外部の入出力（ネットワーク・現在時刻・乱数）に触れる必要があるときは、引数で受け取る。
* 1 テスト 1 つの振る舞い。異常系を先に書く。
* スクリプトは `test`（1 回実行）と `test:watch`。設定は `vitest.config.ts`（`@` を `src` に解決する alias を含める）。

## E2E テスト（Playwright）

* 単一コードベース（Expo Router + react-native-web）なので、UI のロジックの大半は Web 版でも同じものが動く。E2E は Web を主軸にする。
* Playwright の `webServer` で Expo の Web 開発サーバーを起動してから実行する。ローカルでは起動済みのサーバーを再利用する。
* 画面の要素は `testID` で指定する。react-native-web は `testID` を `data-testid` として出力するので、`getByTestId` がそのまま使える。ロールや表示文言で取れる要素は、それを優先してよい。
* 業務上意味のある単位で切る（利用者が達成すること、守られるべき制約）。1 画面を 1 つずつなぞるテストは書かない。
* 正常系だけでなく、失敗や不正な入力の流れも含める。
* API のレスポンスは、Playwright の `page.route` で差し替えられる。実物のバックエンドに当てるか、差し替えるかは、バックエンドの有無に合わせてアプリが決める。
* スクリプトは `e2e`。設定は `playwright.config.ts`。
* 実行の成果物（`test-results/`、`playwright-report/`）は `.gitignore` に入れる。

### E2E で確かめられないこと

Playwright は Web 版しか動かせない。権限ダイアログ、ジェスチャ、`expo-secure-store` など、ネイティブ固有の動きは対象外になる。これらを自動で確かめたいアプリは、Maestro などをそのアプリで追加する（テンプレートには含めない）。

## テストを書かないもの

* 生成されたコード（`src/api/generated/`）
* 分岐のない値の詰め替え・受け渡し
* フレームワーク・ライブラリの動作そのもの
* 画面の見た目（人間が目視で確かめる）
